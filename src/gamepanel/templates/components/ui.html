{# Panel interface components. This file's rule: nothing here knows what a server, a backup or an alert is. They are generic pieces - button, badge, menu, header - which is why they can be used by any screen without dragging along another screen's context. Every piece that fires a POST builds its own CSRF field. Before, that was a line copied into ~40 forms; forgetting it there is a button that returns 400 in production and in no test. #} {# --------------------------------------------------------------- button / link A single component for both, because for whoever uses the panel there is no difference: with `href` an anchor comes out, without `href` a button comes out. #} {% macro button(label, href='', variant='', size='', icon='', type='submit', title='', confirm='', block=false, extra='') -%} {%- set classes = ['btn'] -%} {%- if variant %}{% set classes = classes + ['btn--' ~ variant] %}{% endif -%} {%- if size %}{% set classes = classes + ['btn--' ~ size] %}{% endif -%} {%- if block %}{% set classes = classes + ['btn--block'] %}{% endif -%} {%- if href -%} {%- if icon %}{{ icon }}{% endif %}{{ label }} {%- else -%} {%- endif -%} {%- endmacro %} {# ------------------------------------------------------------------ POST action A single-button form. It exists because every action that changes something in the panel is a POST with CSRF - and writing that by hand thirty times is how that field ends up missing in one of them. #} {% macro action(url, label, variant='', confirm='', icon='', size='', fields={}, block=false, title='') -%}
{%- for name, value in fields.items() %} {%- endfor %} {{ button(label, variant=variant, size=size, icon=icon, confirm=confirm, title=title, block=block) }}
